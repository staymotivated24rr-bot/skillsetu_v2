## Authentic Python upgrade — 2026-10-02

- Founder specification is preserved in `docs/AUTHENTIC_READINESS_SPEC.md`. Python receives authentic content first; shared task, bank, storage, evidence, confidence, branching, reporting and shell architecture is generic. Data Analyst and Java retain their existing banks and lessons.
- Keep every legacy assessment and lesson ID and authored bank. Add immutable `AssessmentBank` rows, task evidence, and separate versioned repair runs. Never overwrite a bank ID; seed compares its SHA-256 digest and rejects changed content. Each new attempt records role, bank, assessment/content versions and a skill/target/importance snapshot. Existing attempts remain `legacy-v1` and keep their original answers/scores/progress. New repair mastery does not erase legacy lesson mastery.
- Two Python baseline variants and three reassessment variants contain 68 tasks each across four work contexts. Thirteen technical topics have executed code tasks; remaining topics use authored explanation rubrics. Seventeen skills retain stable IDs/targets/prerequisites. Every skill has four primary opportunities, with explicit secondary mappings for verification, validation and reasoning. Critical skills have six or more opportunities. The longer authentic assessment takes roughly 90–120 minutes; learners can pause and resume. This is a reversible pacing default, not a hiring deadline.
- Bank selection is learner-stable initially, then cycles through all published variants without immediate reuse. Snapshot-based reports expose the chosen version; report selection permits inspecting historical completions.
- Code executes using pinned Pyodide 0.29.3, self-hosted static assets, an opaque-origin sandboxed iframe and a blob Web Worker. The opaque document CSP permits loading only `/python/` assets from the app origin. After initialization, browser network APIs/importScripts/nested workers are disabled. Python import restrictions are defense in depth, not the primary security boundary. No learner Python reaches a Node, Vercel, shell or Neon execution process.
- Evaluate actual function outputs and reject input mutation. Expected outputs remain on the server. Inputs are inspectable; a determined learner can inspect the harness and forge returned outputs. This is prototype learning/diagnosis, not high-stakes anti-cheating certification. Correct solution code exists only in test fixtures. No remote code sandbox, LLM grading, employment promise or statistical confidence claim is added.
- Execution timeout is five seconds after runtime initialization. Loading has a separate 60-second timeout. Timeout/error/unmount destroys the opaque frame and its worker; the next run creates fresh state. Pyodide has an ephemeral virtual filesystem, not the server's filesystem. Browser memory exhaustion is not a certified resource limit.
- Short answers use normalized, bounded whole-concept matching in three weighted rubric dimensions, with partial credit. Ordered steps use pairwise precedence credit. These rules are deterministic, not AI grading; concept matching may misread negation or miss a valid paraphrase. Independent code, ordered verification and transfer evidence keep readiness from depending solely on recognition decisions.
- Skill proficiency is weighted submitted credit for the latest completed bank. Readiness weights these skill scores by role importance. Practice adds zero proficiency points. Evidence-strength labels are descriptive. Confidence also considers cumulative unique task opportunities, types, contexts, independence and transfer across completed banks; repeated tasks are not counted twice. The UI distinguishes latest-bank opportunities from cumulative evidence. Confidence can strengthen while the latest proficiency falls.
- Adaptive stakeholder replies and the next task's revealed constraint depend on the preceding submitted rubric credit. Essential task contracts stay fixed for comparability. Branching varies the authored workplace evidence/constraint, not the scoring denominator or an LLM's improvisation.
- New Python repair modules retain separate immutable content snapshots and first-response records. Six stages cover guided, independent, harder, workplace, verification and transfer work. Five of six strong first responses and a strong final transfer response are required for mastery. A failed response remains failed after a correct retry; new runs preserve older records. The seven-day plan respects prerequisite ordering, estimated effort and already-mastered repair modules.
- Dark semantic tokens replace the light stylesheet. Restrained emerald accent, compact navigation, focused task panels, explicit evidence labels, prioritized roadmap and paper-friendly print styles are shared across all roles. Narrow screens show larger-screen coding guidance and preserve drafts; tasks are not silently skipped or assigned fabricated credit.
- `TEST_DATABASE_URL` is explicit; tests never silently inherit the application's `DATABASE_URL`. Copy `.env.test.example` to ignored `.env.test`. CI uses PostgreSQL 16 plus production Chromium journeys and uploads browser artifacts. Cloud verification uses separate local PostgreSQL databases. No production Neon migration, seed, reset, drop, merge or production deployment is part of this branch's validation.
- Hosted (`VERCEL=1`) builds now prepare static assets/client and compile without running migration/seed commands. This prevents a PR preview build from writing through a database variable shared with production. Apply the additive migration/seed as a separate trusted operation. Local/CI builds may still initialize their configured development database. `/api/health` now checks connectivity/schema availability and returns a sanitized 503 when setup is unavailable.

- Assessment independence means an unaided submitted response, including workplace decisions; guided hints belong to repair modules. Current bank IDs/content version were advanced when this metadata changed, preserving archived content. Print headings wrap and interactive report controls are hidden on paper; PDF visual review verifies this directly.

- Day seven budgets 120 minutes for the fresh authentic bank rather than a short review estimate. A real favicon is served to keep ordinary Chromium journeys free from missing-resource errors.

- Print status badges use a light active surface; the browser checks actual computed foreground/background contrast at 4.5:1 or higher before creating the PDF.
